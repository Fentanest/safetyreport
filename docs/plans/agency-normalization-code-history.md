# 행정기관 단위 정규화: 코드 이력 검토

작성: 2026-09-28. 구현 전 검토 문서. [2014년 이후 법정동 코드 목록](../reference/administrative-region-codes-2014.md)을 근거로 한다.

## 결정된 범위

- 통계에서 같은 기관으로 묶는 단위는 시·군·구청, 경찰서, 소방서 등 **행정기관**이다. 국·과·팀·지구대 같은 하위 조직명은 집계 키와 표시 이름에서 제거한다.
- 답변에서 받은 `처리기관` 원문은 보존한다. 별도의 정규화 결과를 화면·통계·검색에 사용한다. 원문 덮어쓰기는 DB 교환과 변경 추적의 의미를 바꾸므로 하지 않는다.
- 행정구역의 옛 이름과 현재 이름은 유효기간을 가진 코드 이력으로 연결한다. 이름의 앞부분만 치환하거나 가장 긴 문자열을 현재 이름으로 고르지 않는다.

## 계획 검토

### 1. 코드 체계를 분리해야 한다

이번에 받은 것은 10자리 **법정동 지역코드**다. 안전신문고 답변의 `C_MANAGE_ORG`는 7자리 **기관코드**다. 저장소의 과거 화면 자료에 나온 `1811018`은 [공식 기관코드 조회](https://www.code.go.kr/stdcode/orgCodeL.do)에서 광명경찰서로 확인됐지만, 모든 답변에 이 필드가 오는지는 현재 상세 API 원본으로 확인해야 한다. 법정동코드를 처리기관의 코드로 저장하거나 두 코드가 같다고 가정할 수 없다.

지역코드는 기관 이름에 붙는 **관할 지역**을 정규화한다. 기관 자체는 기관코드와 상위기관 계층으로 식별한다. 예를 들어 `경찰청 … 광주동부경찰서 교통과`의 집계 단위는 광주동부경찰서이며, 지역명 변경은 그 기관의 소속·관할 경로를 표시할 때 반영한다.

### 2. 날짜가 있는 목록은 완전한 변경 사건 목록이 아니다

코드마다 현재 기록된 이름·생성일·폐지일·상위 코드가 있다. **후계 코드, 명칭 변경 전 이름, 1:N 분할 관계**는 별도로 제공되지 않는다. 생성일이 비어 있는 코드도 많고, 폐지일이 없는 폐지 코드가 171개다. 따라서 이번 목록만으로 2014년 이후 모든 날짜의 지역 이름이나 후계 기관을 자동 확정할 수 없다.

구현에 쓸 이력에는 `옛 코드`, `새 코드`, `시작일`, `종료일`, `변경 유형(명칭·통합·분할)`, `공식 근거`, `검증 상태`를 기록한다. 시군구 수준의 변경 사건을 우선 수집하고, 한 옛 코드에서 새 코드가 둘 이상이면 자동으로 하나를 고르지 않는다. 인천 중구·동구 개편 같은 분할은 답변의 기관코드나 관할 정보를 추가로 써야 한다.

### 3. 기관 경계에서 자른다

정규화는 기관코드가 있다면 그 코드의 상위기관 계층에서 시·군·구청 또는 경찰서·소방서까지 올라가서 멈춘다. 이름만 있는 기존 DB는 답변일 당시의 전체 기관 경로로 해당 기관 후보를 찾는다. `교통행정과`처럼 여러 지자체에 중복되는 하위 명칭만으로 합치지 않는다.

기관명이 없는 처리중·취하 신고에는 기관을 임의로 채우지 않는다. 공기업이나 특별행정기관은 시군구청으로 바꾸지 않고 각각의 실제 기관으로 남긴다. 기관코드가 폐지·재발급된 경우에는 확인된 기관 이력을 따라 별도 연결한다.

### 4. 두 저장소의 결과가 같아야 한다

서버 웹·모바일 Client·모바일 Standalone의 통계 및 기관 필터가 같은 집계 키를 사용해야 한다. 오프라인 Standalone은 확인된 코드 이력의 버전 고정 사본이 필요하다. 새 DB 열이나 기존 `처리기관`의 의미를 바꿀 경우 양쪽 스키마·DB 교환·API·왕복 테스트를 같은 작업에서 갱신한다(`PROJECT_RULES.md` §3-1).

검증 fixture에는 옛/새 광주동부경찰서와 나주시·서구, 서로 다른 광역단체의 동명 `서구`, 부서명만 바뀐 동일 기관, 기관 공란, 1:N 분할을 넣는다. 표·필터·drilldown·다운로드가 같은 코드 매핑을 쓰는지도 확인한다.

## 검토 결론과 다음 작업

행정구역 이력을 이용한 기관 단위 집계는 가능하다. **지역코드 수집은 완료됐지만 후계 관계와 7자리 기관코드 이력은 아직 수집·검증되지 않았다.** 지금 단계에서 지역명만 보고 DB의 `처리기관` 값을 일괄 변경하면 다른 기관을 합칠 수 있다.

다음 구현 단위는 (1) 공식 변경 공지로 시군구 후계 관계 검증, (2) 기관코드 조회 자료와 현재 상세 API의 `C_MANAGE_ORG` 대조, (3) 읽기 전용 매칭 결과의 `확정/후보/미해결` 분류, (4) 양쪽 저장소에서 같은 정규화 투영과 fixture 검증이다.
