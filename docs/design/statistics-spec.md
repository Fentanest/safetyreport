# 통계 의미와 구현 계약

작성 2026-09-24. 근거 코드: `services/report_stats_service.py`(기준 `17df6cb`), `web/routers/stats.py`, `web/routers/filters.py`,
`services/duplicate_group_service.py`. 현재 동작은 `tests/test_stats_fixture_semantics.py` 가 합성 fixture 로 고정한다.
이 문서의 "현행"은 코드로 확인한 사실, "결정 필요"는 사용자 승인 전 구현하지 않는 항목, "제안"은 리뉴얼 설계안이다.

2026-09-29 코드 대조 정정: 경찰서 뒤 문자열 절단 옵션은 제거했다. 기관명은 registry 조회 결과로 표시·묶고, 미확정이면 원문을 유지한다. 아래 과거 fixture 수치는 변경 전 기록이며 현재 테스트를 정본으로 삼는다.

## 1. 데이터 경계
- 개인 신고 통계(`mysafetymerge_{traffic,parking,other}`)와 Sunwi 전국 행정구역 통계(`sunwi_service`, 대시보드 패널)는 다른 데이터셋이다. 한 차트·한 합계에 섞지 않는다.
- 카테고리는 교통/주정차/기타 세 개이며 서로 배타적이다(merge 테이블 단위). 중복차량(`/data/duplicates`)과 중복군은 겹치는 조회 집합이지 네 번째 카테고리가 아니다.
- `상태`=raw, `처리상태`=canonical 표시 상태, `종결여부`/`보완_미응답`=lifecycle. 통계는 전부 `처리상태` 기준이다.
- 대표건 projection: 기본값은 설정 `use_representative_records`(True→`canonical`). `?dedupe=raw|canonical` 이 있으면 우선. `not_duplicate` 그룹과 `apply_globally=0`(검토 필요) 그룹은 canonical 에서도 원본이 모두 남는다.

## 2. 현행 집계 파이프라인 (기관/담당자/법규 표, `get_agency_stats`)
1. 세 merge 테이블을 읽으며 SQL 에서 먼저 거른다(`_build_stats_query`, :205-253): 연도(**`답변일` 접두어**), 신고일/발생일/답변일/발생시각 범위, 경찰 포함·제외, `&`·`,` 가 없는 단순 텍스트(신고명·위반장소·처리기관).
2. 세 카테고리를 합쳐 대표건 projection(:491-499).
3. pandas 에서 같은 필터를 다시 적용(:535-565) — AND(`&`)/OR(`,`) 텍스트, `agencyExact`(단일어일 때만 exact).
4. 취하 제외(`exclude_withdraw`, :567) → 법규 목록 산출 → 법규 필터(`__없음__` = 빈 법규, :578-582).
5. 기관코드 registry 현행명·통계 키 적용(코드 미확정이면 원문) → 결측 기본값(기관 `알수없음`, 담당자 `미지정`, 상태 `처리중`).
6. **담당자 없음 + 처리중/진행/진행중/검토중/취하** 행 제거(:594).
7. 기관 / 기관+담당자 / 법규 로 group. 경찰·비경찰 표는 기관명에 '경찰' 포함 여부로 나눈 부분집합.

## 4-1. 결정: 금액 없는 과태료의 추정 (2026-09-24 사용자 결정)

- 답변 맥락(LLM 해석)이나 처리기관·주소로 가중 여부를 판별하지 않는다. 유형마다 **일반적으로 알려진 기본 금액 1개**를
  "추정(최저 기준)"으로 넣는다. 가중(2시간 이상, 어린이보호구역, 고속도로, 차량 이용 투기 50만원 등)은 반영하지 않으므로 추정은 실제보다 작거나 같다.
- 확정 금액(과태료 칸에 `숫자원`)과 추정 금액은 **합치지 않고 따로** 보인다: "확정 N원 + 추정(최저) M원(K건)".
- 금액 파싱에서 `포상금` 이 붙은 금액은 제외한다(부천시 폐기물 답변의 "신고포상금(6,000원)" 사례).

## 8. 성능
필터마다 세 테이블을 한 번씩 읽고 projection 을 한 번 한다. 차트용 값을 추가할 때 같은 DataFrame 에서 계산해 재조회하지 않는다.
캐시를 도입하면 크롤링 완료·데이터 수정·중복 대표건 변경·백업 복원 시 무효화한다.

## 9. 통계 화면 개편 (2026-09-28, 사용자 지시 — PC·모바일 공통)

화면 순서: 공통 조건(분류·답변 연도·위반법규·상세 조건, 적용 조건 칩과 개별 해제) → 요약 카드 6개 → 신고 지도·월별 처리 추이·처분 분포·위반 유형
→ 상세 통계(여섯 보기·검색·행 수·열 선택·CSV·선택 항목 상세) → 전국 안전신고 현황(Sunwi, 대시보드에서 옮김).
현재 차트는 아래 코드 대조 정정에 따라 처리결과/처분 및 **위반법규별 현황**을 사용한다.
시안의 색·숫자·문구는 쓰지 않았다(배색은 `tokens.css`, 수치는 전부 서버 집계). 인사이트·자동 해설 박스는 만들지 않았다.

### 9-1. 범위 규칙
- 공통 조건은 요약·지도·차트·상세표에 모두 적용한다. 여섯 보기(기관별·담당자별·경찰 기관·경찰 담당자·비경찰 기관·비경찰 담당자)는 상세 영역의 집계 단위·기관 범위만 바꾼다.
- 상세표 검색(기관명·담당자명만, 숫자 열 제외)·정렬·열·쪽 이동은 상세 영역에만 적용하고, 상세 머리의 범위 문구에 드러낸다.
- 표에 들어가지 않는 신고(처리기관 없음, 담당자 표는 담당자 없음)는 요약 총 건수와의 차이를 범위 문구에 "처리기관이 없는 N건은 기관 표에 없음"으로 표시한다.
- 날짜 기준은 답변일로 고정(연도·월별 추이). '처리 기준/신고 기준' 전환은 없다. 연도 선택 시 답변일 없는 신고는 기존대로 빠지고, '전체'에는 포함된다.

### 9-2. 요약 카드 (`/stats/overview` 한 분류)
| 카드 | 값 | 보조 정보(분모·표본) |
|---|---|---|
| 총 건수 | `total` | 처리 중 `processing` · 보완요청 `supplement` |
| 답변 완료 | `completed` | 총 N건 중 %, 수용·일부·불수용/기타 |
| 과태료 건수 | `disposition.fines` | 총 N건 중 % |
| 경고·범칙금 건수 | `disposition.warnings` | 총 N건 중 % |
| 평균 처리기간 | `avg_days`(완료 신고, 달력 날짜 차이) | 유효 표본 `avg_days_count`, 날짜 역전 제외 수 |
| 확정 과태료 | `fine_amount.confirmed_amount` | 금액 확인 건수·금액 미확인 건수, 추정(법정 최저) 금액·건수는 별도 줄 |
- 과태료 금액 카드는 **선택한 분류**를 따른다(예전 '교통위반 한정' 배너 대체 — 주정차·기타의 과태료도 같은 규칙으로 보인다). API `traffic_total_fine` 은 그대로.
- 증감 화살표·증감률은 없다(검증된 이전 기간 비교 없음). 분모 0 은 '—', 실제 0 은 0.
- PC 카드는 목록이 같은 조건을 재현할 수 있을 때만 링크다(총 건수·답변 완료·과태료·경고/범칙금 → `/data/<분류>` + 법규·답변일 범위·상세 조건). 경찰기관 제외/만, AND·OR 기관 검색이 걸리면 링크를 만들지 않는다.

### 9-3. 차트
- **월별 처리 추이**: 막대 = 답변월 처리 건수(`monthly_answered`), 선(모바일은 가는 막대) = 그중 과태료(`monthly_answered_fine`). 신고일 계열·처리율은 그리지 않는다(기준이 다름). API 의 `monthly_reported` 는 그대로 남는다.
  연도 선택 시 그해 1월 ~ (12월과 이번 달 중 이른 달), 전체면 첫 답변월 ~ 마지막 답변월. 미래 달을 0 으로 그리지 않고 이번 달은 '집계 중' 빗금/흐린 막대. 기간이 길면 가로 스크롤.
- **처분 분포**: 일곱 항목(과태료·경고/범칙금·불수용/기타·처리중·처분 미확인·처분 대상 아님·기타·미분류)을 각각 총 건수 대비 막대로. 앞 세 항목은 한 신고에 겹칠 수 있어(`overlap`) 100% 도넛을 쓰지 않았다. `overlap>0` 이면 문구로 알린다.
- **위반 유형별 현황**: 신고명 원문 기준 상위 6개 + '전체 N개 유형 보기'(전체 목록 스크롤). 비율 분모 = 분류 총 건수. LLM 분류 없음.
- **신고 지도(PC)**: `/stats/map` 과 같은 마커·클러스터·팝업(`static/ui/report-map.js`)으로 현재 분류·조건의 좌표를 비동기로 받는다(요청 번호·AbortController 로 늦게 온 응답 무시, 실패 시 재시도). '지도 표시 N건 / 대상 M건'으로 좌표 없는 건을 밝히고 '전체 지도 열기'는 같은 조건으로 연다. 모바일은 통계 안에 지도를 넣지 않고 앱바 '지도'·'신고 지도 열기'로 기존 지도 화면(연도·분류)을 연다.
- 차트·표·상세 패널의 처분 색은 같은 의미색: 과태료 `--sr-status-fine`, 경고/범칙금 `--sr-status-penalty`(신규 토큰), 불수용 `--sr-status-reject`, 처리중 `--sr-status-processing`, 미확인·미분류 `--sr-status-unknown`(신규), 처분 대상 아님 `--sr-status-withdraw`. 모바일은 `server_palette.dart` 같은 계열 + `StatusTone`.

### 9-4. 상세표·선택 항목 상세(PC)
- 18개 표·머리글 글자(열 선택 저장 키 `stats_column_visibility`)·합계 행 칸 수는 그대로. 숫자 열은 오른쪽 정렬, 첫 식별 열 고정, 모든 열을 켜면 표 영역 안에서만 가로 스크롤.
- 합계 행 평균 처리기간을 행의 `avg_days_count`(표본 수)로 가중하도록 고쳤다(예전: 행 총 건수 가중 — 처리중 건이 많은 기관이 과대 반영됨). 별점은 전처럼 평가 수 가중.
- 행 선택 = 상세 패널(넓으면 표 옆 340px, 좁으면 오른쪽 드로어). 목록 이동은 패널의 '해당 신고 내역 보기'(행 `data-href`), '지도에서 보기'는 `targetAgency/targetPerson` 을 붙여 `/stats/map` 으로. 분류·보기를 바꾸면 선택을 해제한다.
- 목록·지도에서 돌아오면 같은 주소(조건)일 때만 보기·검색어·행 수·표별 정렬/쪽·선택·스크롤을 되살린다(sessionStorage `stats_view_state`).
- CSV 내보내기: 검색·정렬이 적용된 현재 보기의 **전체 행**(모든 쪽). 확정/추정 과태료·금액 미확인·처분별 건수와 비율·별점·평가 수를 별도 열로. 형식은 CSV(UTF-8 BOM).
- 순번(순위) 열은 두지 않고 '정렬: 기준 · 순서는 평가 순위가 아님'을 표시한다.

### 9-5. 모바일
- 2열 요약 카드(태블릿 폭 3열) → 월별 처리 추이 → 처분 분포·위반 유형은 '펼치기'. 요약은 접을 수 있고 '상세 통계'로 바로 이동한다.
- 여섯 보기는 3+3 두 줄로 모두 보인다. 검색(기관·담당자명)·정렬(총 건수·과태료·확정 과태료·처리기간·별점·이름). 목록은 자르지 않는다(TOP 10 없음). 금·은·동 순위 표시는 없앴다.
- 카드: 이름·총 건수 → 평균 처리(표본)·별점(평가 수)·확정/미확인/추정 금액 → 처분 일곱 칸(3열) → 구성 막대. 탭하면 예전처럼 해당 기관/담당자 목록.
- 요약만 실패하면 요약 자리에 안내와 '다시 시도'. 조건을 빠르게 바꾸면 요청 번호로 늦게 온 이전 응답을 버린다. 위반법규 선택은 떠 있는 버튼 대신 조건 줄의 검색 가능한 선택창.

### 9-7. 2026-09-28 추가 결정 (실제 DB 조사 반영 — `.agent-runs/muse-disposition/REPORT.md`, Muse)
- **표는 답변 완료 신고만**: 기관·담당자·법규 표에는 처리상태가 수용·일부수용·불수용·기타·답변완료인 신고만 넣는다(S-10 "기관이 있으면 처리중도 포함" 대체).
  처리중은 답변이 없어 처리기관·담당자도 없는 게 정상이다(실제 DB 처리중 83건 전부 기관 없음). 취하·보완요청·이송도 표에 들어오지 않는다. 행 필드 `in_progress` 는 호환을 위해 남기며 항상 0이다.
  표의 '처리중' 열과 모바일 카드의 '처리중' 칸을 없앴다(예전 서버 응답에 값이 있을 때만 모바일에 보임).
- **'처분 미확인' → '과태료 미확인'**(필드 `disposition_unknown` 그대로): 답변은 완료됐지만 과태료 여부·금액을 답변에서 읽지 못한 신고.
  교통위반 메뉴의 수용·일부수용·기타 + 금액·범칙금·경고 문구 없음(파서 '미확인'), 그리고 **주정차·버스전용차로·쓰레기 메뉴의 일부수용**(사용자 결정: 보통 과태료 처분이 아님).
  파서는 이제 이 일부수용에 금액 없는 '과태료' 대신 '미확인'을 넣는다(서버 `parser.py`, 모바일 `standalone_parser.dart`, 벡터 `contracts/parser-vectors.json`).
  이미 저장된 일부수용·처분 빈값도 통계에서는 과태료 미확인으로 센다(재수집 없이). 목록의 `fine=미확인` 필터는 저장값 '미확인'만 찾는다.
  대시보드 교통위반 카드 '미확인' → '과태료 미확인'. 금액 없는 '과태료'(버스·주정차·쓰레기 수용)는 그대로 '금액 미확인 과태료'이며 두 값은 겹치지 않는다.
- **처분 분포 분모 = 답변된 신고**(총 건수 − 처리중). 처리중 줄은 없애고 "처리 중(답변 전) N건은 뺐습니다"로 적는다. 요약 카드의 '처리 중 N건'은 그대로.
- 실제 DB(3,071건, 취하 제외 2,949) 분포: 과태료 1,497 · 경고·범칙금 1,013 · 불수용·기타 304 · 처리중 83 · 과태료 미확인 51(+ 주정차 일부수용 10건 이동 → 61) · 처분 대상 아님 1.
