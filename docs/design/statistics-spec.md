# 통계 의미와 구현 계약

작성 2026-09-24. 근거 코드: `services/report_stats_service.py`(기준 `17df6cb`), `web/routers/stats.py`, `web/routers/filters.py`,
`services/duplicate_group_service.py`. 현재 동작은 `tests/test_stats_fixture_semantics.py` 가 합성 fixture 로 고정한다.
이 문서의 "현행"은 코드로 확인한 사실, "결정 필요"는 사용자 승인 전 구현하지 않는 항목, "제안"은 리뉴얼 설계안이다.

## 1. 데이터 경계
- 개인 신고 통계(`mysafetymerge_{traffic,parking,other}`)와 Sunwi 전국 행정구역 통계(`sunwi_service`, 대시보드 패널)는 다른 데이터셋이다. 한 차트·한 합계에 섞지 않는다.
- 카테고리는 교통/주정차/기타 세 개이며 서로 배타적이다(merge 테이블 단위). 중복차량(`/data/duplicates`)과 중복군은 겹치는 조회 집합이지 네 번째 카테고리가 아니다.
- `상태`=raw, `처리상태`=canonical 표시 상태, `종결여부`/`보완_미응답`=lifecycle. 통계는 전부 `처리상태` 기준이다.
- 대표건 projection: 기본값은 설정 `use_representative_records`(True→`canonical`). `?dedupe=raw|canonical` 이 있으면 우선. `not_duplicate` 그룹과 `apply_globally=0`(검토 필요) 그룹은 canonical 에서도 원본이 모두 남는다.

## 2. 현행 집계 파이프라인 (기관/담당자/법규 표, `get_agency_stats`)
1. 세 merge 테이블을 읽으며 SQL 에서 먼저 거른다(`_build_stats_query`, :205-253): 연도(**`답변일` 접두어**), 신고일/발생일/답변일/발생시각 범위, 경찰 포함·제외, `&`·`,` 가 없는 단순 텍스트(신고명·위반장소·처리기관).
2. 세 카테고리를 합쳐 대표건 projection(:491-499).
3. pandas 에서 같은 필터를 다시 적용(:535-565) — AND(`&`)/OR(`,`) 텍스트, `agencyExact`(단일어일 때만 exact).
4. 취하 제외(`exclude_withdraw`, :567) → 법규 목록 산출 → 법규 필터(`__없음__` = 빈 법규, :578-582).
5. 경찰 기관명 정규화(`normalize_police`: '…경찰서' 뒤를 자름, :587) → 결측 기본값(기관 `알수없음`, 담당자 `미지정`, 상태 `처리중`).
6. **담당자 없음 + 처리중/진행/진행중/검토중/취하** 행 제거(:594).
7. 기관 / 기관+담당자 / 법규 로 group. 경찰·비경찰 표는 기관명에 '경찰' 포함 여부로 나눈 부분집합.

## 5. 리뉴얼 통계 화면 지표 계약 (제안)

원칙: 서버의 **한 번의 집계 호출 결과**를 KPI·차트·표가 함께 쓴다. 새 값은 Jinja 에 `tojson` 으로 같은 요청 안에서 내려 필터 불일치를 막는다.
브라우저의 현재 페이지 행으로 통계를 계산하지 않는다. `/api/v1` 응답 필드는 추가만 한다.

|---|---|---|---|
| KPI: 총 신고 | 현재 필터·projection·취하 설정을 적용한 모집단 | "필터 적용 N건" 과 분모 설명 툴팁 | 제안 |
| KPI: 답변완료 / 수용률 | 답변완료 = 수용·일부·불수용·기타·답변완료 | 수용률 분모 = 답변완료 건수(처리중·보완 제외)라고 표기. 0 이면 "—" | 제안(분모 **결정 필요**) |

## 6. 모바일 overview 와의 정렬
모바일 세션이 `feature/stats-overview-api` 브랜치(미커밋)에서 `/api/v1/stats/overview` 와 공통 헬퍼
(`_load_stats_frames` / `_apply_stats_row_filters` / `_apply_stats_law_filter` / `get_stats_overview`)를 만들고 있다.
웹 통계 상단은 **같은 함수**를 써야 한다. 순서: (1) 그 브랜치가 `dev` 에 합쳐진 뒤 (2) D-STAT-3 결정을 양쪽에 반영하고 (3) 웹 차트를 올린다.
그 전까지 웹 쪽에서 별도 집계 함수를 새로 만들지 않는다.

2026-09-24 해당 브랜치 커밋 현황(읽기만 확인): `8297689`(stats/overview API), `3ce6bd7`(행별 `fine_amount_unknown`, **법규 필터를 부분 일치→완전 일치**로 변경, 모바일 결정 S-05·S-09).
법규 완전 일치는 웹 통계 법규 사이드바(값이 `available_laws` 원문)와 호환되지만, 병합 시 `test_stats_fixture_semantics` 기대값과 웹 드릴다운(`/data/<cat>?law=`, 목록은 여전히 부분 일치)을 함께 확인한다.

## 8. 성능
필터마다 세 테이블을 한 번씩 읽고 projection 을 한 번 한다. 차트용 값을 추가할 때 같은 DataFrame 에서 계산해 재조회하지 않는다.
캐시를 도입하면 크롤링 완료·데이터 수정·중복 대표건 변경·백업 복원 시 무효화한다.
